# Enamel design system

Enamel is a design system for controller-first apps that feel at home in Steam's Gaming Mode: Steam's own baseline with one accent colour on top, like a thin coat of enamel over steel. It is the shared set of tokens and rules those apps use for their look. Coral is the default accent.

Tokens live in `tokens/enamel.css`. Components live in `components/enamel-components.css`, with one small behaviour script, `components/enamel-components.js`, for the picker dialog and the toast. The style guide has five pages: `docs/overview.html` (overview), `docs/index.html` (token reference), `docs/components.html` (components), `docs/motion.html` (motion) and `docs/resize.html` (every component in frames you can resize, and at fixed widths).

## Part 2: Rules

- Use only `--en-` tokens. Never hard-code a colour, size or radius.
- Apps use the semantic tokens (Group C), not the grey ramp directly.
- The accent appears only for: selected side-menu item, toggle on, slider and progress fill, primary button, status text, "new" dot, the focus ring, the focus underside, the progress speckle's fill and the page speckle's occasional fleck.
- Focus: accent ring with a soft glow on tiles, accent ring on toggles; cream fill with dark semibold text on a 4px accent underside on buttons, fields and picker rows; a focused row on a page lifts to `--en-surface-control`, with muted text stepping up to `--en-text-soft`.
- Satin, never gloss.
- Patterns live on the page ground and in progress fills only. Nothing you can select is ever patterned.
- One border per element: no rims inside rings, no lips inside outlines.
- One focus style per kind of element: cream on a coral underside for things you press, a coral ring for tiles, a lift for rows.
- Cream is a neutral; the accent stays the only colour.
- Only things you press move physically.
- Every size is a multiple of 4 in its own unit (0.25rem if it grows with text, 4px if it does not) unless a listed exception applies.
- Ask of every size: should it grow when the user makes text bigger? Yes is rem, no is px. Never set the root font size.
- Only one element shows focus at a time.
- Labels on the accent use `--en-accent-ink`, never white.
- Green, yellow and red are for success, warning and error only.
- System font only. Never add a web font.
- No layout is tied to a screen size, a device or an aspect ratio. Nothing in tokens, components, examples or docs names one as a layout target.
- Layouts adapt to the space they are given: relative units, min(), max() and clamp(), intrinsic sizing, wrapping, and container queries, so a component responds to its own box rather than to the whole screen.
- Breakpoints, where needed, come from the content and are named by what they do ("panels stack when they cannot both fit at their minimum width"), never by a device.
- Devices are for testing, never targets.
- The smallest supported box is 20rem wide by 15rem tall (320px wide and 240px tall at the browser's normal font size). It is set by its content: a list row with its title and a toggle, and the hint bar with at least two hints on one line, fit in it without overlapping, and every focus ring stays fully visible. More hints wrap onto another line. Below that size the page scrolls; nothing overlaps or is cut off.
- No Valve assets: no icons, logos, fonts or class names.
- Never put accent-coloured text on `--en-surface-control`. Keep status text on the page or on a row.
- When a row is focused, muted text inside it steps up to `--en-text-soft`.
- Build screens from these components before writing any new CSS.
- Apps size their own layout with the same scale, in rem or with Enamel's tokens, never with fixed pixels for anything that holds text; lines, corners, shadows and side padding that would squeeze text stay in px.
- The keyword transparent is allowed. The style guide's own layout widths in docs/site.css are allowed.
- Motion uses only the motion tokens.
- Motion marks focus or a change of state, nothing else.
- The focus pulse stops after about five seconds.
- Every component must work in reduced motion.

## Part 3: Components

Link `tokens/enamel.css`, then `components/enamel-components.css`. For the picker dialog and the toast, also load `components/enamel-components.js` (see "Behaviour script" below); without it they still look right. Class names start with `en-`. State comes from standard attributes, never extra classes. Every focus style applies on `:focus-visible` and on `data-focused="true"`, for apps that manage focus themselves. Sizes with no token are component variables (`--en-c-`) at the top of the file. A size is in rem if it should grow with the user's text and in px if not (see "Scaling" below), and each component is sized by its content and the space it is given: text wraps, rows of hints, tabs and buttons wrap, and heights are minimums. A larger font may make a target bigger, never smaller.

### Hint bar
- Classes: `.en-hintbar`, `.en-hint`, `.en-glyph`, `.en-glyph--shoulder` (for L1 and R1).
- State: none.
- Use it along the bottom of every screen to show what each controller button does. It is at least `--en-size-bar` tall; hints that don't fit on one line wrap onto another and the bar gets taller, so no hint is cut off. Its side padding is the gutter, or less in a narrow space, so two hints share a line in the smallest supported box.
- Motion: none.

### Tabs
- Classes: `.en-tabs`, `.en-tab`, `.en-tab__count`, `.en-dot`.
- State: `aria-selected="true"` on the selected tab.
- Tabs show a ring for keyboard use only; on a controller they are switched with L1 and R1.
- Use them to switch between the main lists of a screen. Add `.en-dot` when a tab has something new. A set of tabs that doesn't fit on one line wraps onto another, and a single tab wider than its space wraps its label.
- Motion: the selected pill's background and text colour fade over `--en-motion-medium`. A new dot fades in over `--en-motion-medium`.

### List row
- Classes: `.en-rows`, `.en-row`, `.en-row__meta`.
- State: focus (`:focus-visible` or `data-focused="true"`) lifts the row; its meta text steps up to `--en-text-soft`.
- Use it for any vertical list: films, episodes, settings. A row is at least `--en-size-row` tall, and at least `--en-size-row-control` when a toggle or a button sits at its end; a long title wraps and makes it taller. Rows in a list are `--en-space-gap` apart. Put a list `--en-space-gutter` from the side of the screen.
- Motion: on focus, and when focus leaves, the background and text colours fade over `--en-motion-fast`.

### Message in a row
- Classes: `.en-row__message` (with `role="status"` and `aria-live="polite"`), inside a `.en-row`, holding a `.en-icon` (the error mark: a filled disc with an exclamation mark, `aria-hidden="true"`) and the text.
- State: empty while there is nothing to say; the icon and text inside it while it shows.
- Use it to say, inside the row itself, why a row can't be chosen. Keep the element in the row, empty, and put the icon and text in it when it should show, so screen readers read it politely when it appears; while it is empty it takes no space. It is in the error style: white text after a red disc with a dark mark, readable whether the row is focused or not (red text is too faint on the greys). Inside a picker, on the cream fill of a focused row, its text turns dark like the row's own description. It sits on a line of its own under the row's content, so the row grows taller, never wider; a long message wraps.
- Motion: it fades in over `--en-motion-fast` when it appears. In reduced motion it simply appears.

### Badge
- Classes: `.en-badge`, inside a `.en-row` or after a `.en-tab`'s label.
- State: none of its own. On a focused row, a selected tab or a picker row's cream fill it turns to the page colour.
- Use it for a short label on a row (the folder already chosen as "Movies") or after a tab's label ("Beta"). It is muted: soft text in capitals on the control grey. Only its colours change when its row is focused or its tab selected, so the row or tab never changes size, and its text is part of the row's or tab's accessible name. A badge that doesn't fit beside the row's title or the tab's label moves under it, and a long badge wraps.
- Motion: none of its own. On a row it changes colour with the row, over `--en-motion-fast`.

### Group band
- Classes: `.en-band` (on a heading element), `.en-band--outline`, `.en-band__name` (holding the `.en-icon` first, then the name, so the two stay together), `.en-band__count`.
- State: none. It never takes focus.
- Use it above each group of list rows, with the group's icon, its name (shown in capitals) and how many it holds on the right, then the group's `.en-rows` under it. The two kinds differ by fill and by icon, never by colour alone: the filled band for storage on the device itself, with a drive; the outlined band, drawn with a line as thick as its icon's, for storage you can take out, with a card. Draw these icons as on the Components page; they are Enamel's own. When the name and count don't fit side by side, the count moves onto a line of its own.
- Motion: none.

### Tile
- Classes: `.en-shelf`, `.en-tile`, `.en-tile--large`, `.en-tile__frame`, `.en-tile__title`, with a `.en-progress--thin` between frame and title.
- State: focus draws the accent ring around the frame and its track.
- Use it for a video on a horizontal shelf. Use the large tile for the one item the screen is about. A shelf is a size container and its tiles take their width from it: a tile is two fifths of the shelf, between 10rem and 16rem, and a large tile three quarters, between 12rem and 28.25rem. Tiles are `--en-c-shelf-gap` apart. Put shelves and grids `--en-space-gutter-grid` from the side of the screen. A portrait cover is `--en-size-tile-portrait` wide and one and a half times that tall; Enamel has no portrait tile component yet. The shelf scrolls sideways when its tiles don't all fit, and its padding and scroll padding keep a focused tile's ring and growth inside it at any size.
- Motion: on focus the tile grows to `--en-focus-scale` over `--en-motion-slow`, without moving its neighbours. The ring appears `--en-focus-ring-start` thick and narrows to `--en-focus-ring-width` over `--en-motion-ring`. Then it breathes `--en-pulse-count` times (each breath `--en-pulse-duration` with `--en-ease-pulse`, dimming to `--en-pulse-min`) and rests fully visible, about five seconds after focus arrived. Losing focus reverses over `--en-motion-fast`. The shelf's padding leaves room for the thick ring and the growth.

### Button
- Classes: `.en-button`, `.en-button--primary`, `.en-button--icon`.
- State: focus (cream fill and dark semibold text, on a 4px accent underside); `:active`, or `data-pressed="true"`, while pressed (pressed cream); `disabled`. A primary button is the accent colour until it is focused. A stylesheet can't see a controller's press, so an app sets `data-pressed="true"` while A is held; without it, only that movement is missing.
- Use it for actions. Give a screen at most one primary button, for its main action. A button is at least `--en-size-button` tall, and never below the 44px touch target. An icon or a glyph sits `--en-space-icon` from its text. An icon button is square, as tall as a button, and grows with a larger font.
- Motion: when focus arrives the face rises `--en-lift` over `--en-motion-medium` with `--en-ease-standard` as its underside appears; when focus leaves it settles back over `--en-motion-fast`. Pressed, it drops onto its underside over `--en-motion-fast`, and release springs it back over `--en-motion-medium`. Keep what it sits in from clipping the rise. In reduced motion focus switches to cream at once and a press only darkens.

### Toggle
- Classes: `.en-toggle`, on a `<button>`.
- State: `aria-pressed="true"` for on, `"false"` for off; focus draws the accent ring. The off thumb is cream.
- Use it for an on or off setting, at the end of a row.
- Motion: when it is switched, the thumb slides and the track and thumb colours fade over `--en-motion-medium`. As in Gaming Mode, its focus ring appears at once and does not breathe.

### Progress
- Classes: `.en-progress`, `.en-progress__fill`, `.en-progress--thin`, `.en-progress__head`.
- State: the custom property `--value` (a percentage) on `.en-progress`.
- Use it to show how far something has got. Put the head line above it when the number or status matters. It is a sunken dark track with a hairline edge and an accent fill speckled in cream, 12px tall, or 8px with `.en-progress--thin` under a tile. Inside a toast it goes on a line of its own.
- Motion: the fill glides to each new value over `--en-motion-slow`.

### Side menu
- Classes: `.en-menu`, `.en-menu__item`.
- State: `aria-current` on the current item; focus shows the control surface and an accent bar.
- Use it for the list of places down the left of a screen. It is `--en-c-menu-width` wide, or as wide as its space if that is narrower. An item is at least `--en-c-menu-item-height` tall; a long label wraps and makes it taller.
- Motion: on focus the accent bar grows from the centre of the item and the colours fade, over `--en-motion-medium`. The current item's glow fades in and out over `--en-motion-medium`.

### Action bar
- Classes: `.en-actionbar` (a `<header>`), holding `.en-button` and `.en-button.en-button--icon`; `.en-icon` on an inline SVG icon.
- State: the buttons' own (focus, `disabled`).
- Use it across the top of a screen, with its buttons on the right. It stays docked (sticky) and opaque while the content scrolls underneath. On one line it is as tall as a button plus `--en-space-tight` above and below. It is full width; when its buttons don't fit on one line they wrap onto another and the bar gets taller, so a label is never cut short (a single button wider than the bar wraps its label inside itself). An icon button always has an `aria-label`. Draw icons as inline SVG with `stroke="currentColor"` and `aria-hidden="true"`, so they turn dark on the cream focus fill; never use Steam's icons.
- Motion: none of its own. Its buttons behave like every other button.

### Picker dialog
- Classes: `.en-dialog` (on a `<dialog>`: the almost black, blurred layer over the page, stopping at the top of the hint bar however tall it is), `.en-picker` (the panel), `.en-picker__title` (the question, for a confirm), `.en-picker__rows`, `.en-picker__row` (a `<button>`, with its title in a first `<span>` and an optional `.en-picker__desc`), `.en-picker__cancel` (on the last row, Cancel, after a small gap).
- State: `open` on the dialog; `data-focused="true"` (or `:focus-visible`) on the focused row; `:active` or `data-pressed="true"` on a pressed row; `aria-current="true"` on the current choice; `autofocus` on the row to focus first; `data-closing="true"` on the dialog while it leaves.
- Use it for three things. An action list: rows of actions, no current choice. A choice list: the current choice marked with `aria-current="true"`. A confirm: the question as `.en-picker__title`, the action row, then Cancel with `autofocus`, so a stray press changes nothing. Give each row a `value`. The panel is as wide as its longest row, at least a quarter and at most two thirds of the space its dialog gives it (the dialog is a size container, so the panel follows its own box, never the screen); longer text wraps. Rows are at least 4.5rem tall with a title only and 6rem with a description.
- Inside a picker the focused row behaves like a button: cream with dark semibold text (title and description both `--en-focus-fill-ink`), on its accent underside. Rows are `--en-lift` apart, so a row that has risen covers no neighbour. The current choice, unfocused, is on the control grey with its description in `--en-text-soft`.
- Motion: the darkened, blurred layer appears at once and the panel fades in over `--en-motion-dialog` with `--en-ease-standard`; closing, the panel fades out the same way and the layer goes with it. The focused row rises and presses as a button does. In reduced motion it simply appears and disappears, and rows switch at once.

### Toast
- Classes: `.en-toast` (with `role="status"` and `aria-live="polite"`), `.en-toast__icon` (optional, holding a `.en-icon`, `aria-hidden="true"`), `.en-toast__text`.
- State: `hidden` while not showing; `data-closing="true"` while it leaves.
- Use it for a short message about something that just happened. It sits at the bottom right, flush with the right edge, just above the hint bar however tall it is. It is as wide as its text, up to `--en-c-toast-width` (28rem) and never wider than its space less a gutter; longer text wraps. It never takes focus and never blocks taps. One at a time: a new one replaces the old. It stays three seconds after its last update.
- Motion: it slides in from the right edge over `--en-motion-slow` with `--en-ease-enter`, and leaves by fading out where it is, over the same time with the same curve, as Steam's own toast does. In reduced motion it simply appears and disappears.

### Step label
- Classes: `.en-steplabel`, on a `<span>` inside the page title's heading element, before the title.
- State: none.
- Use it above the title of each screen in a short flow ("Step 1 of 3"). It is small and muted, on a line of its own. Inside the heading, screen readers read the step and the title together as one heading.
- Motion: none.

### Numbered steps
- Classes: `.en-steps`, on an `<ol>` of plain `<li>` items.
- State: none.
- Use it for two to five short steps someone follows in order. Each number sits in a round mark as big as a button glyph, on the control grey; when a step wraps, its text lines up after its number.
- Motion: none.

### Stat panel
- Classes: `.en-statpair`, `.en-statpanel` (with `role="img"` and an `aria-label` holding its whole text, such as "124 movies, SD card › Films"), `.en-statpanel__counts`, `.en-statpanel__count`, `.en-statpanel__number`, `.en-statpanel__path`, `.en-statpanel__notset`.
- State: none. It never takes focus and has no hover or focus state.
- Use it to show one or two counts, each a large number with its word, with the folder they refer to under them as a place path. In place of the counts it can show "Not set", with its second line saying which kind it is, so two of them can be told apart. A stat pair puts two panels side by side, and they stack when they cannot both fit at `--en-c-statpanel-min`; the pair is a container that wraps, so it follows its own space, and both panels share a row's height. A panel outside a pair takes the width of its space. It uses no accent and no success, warning or error colour. Write the path's › as part of the text.
- Motion: none.

### Note
- Classes: `.en-note`, on a `<p>`, with an optional `.en-icon` first (`aria-hidden="true"`; draw it as on the Components page).
- State: none. It never takes focus.
- Use it for one plain line of neutral information under other content ("12 files in Films look like episodes."). It never blocks anything and never goes inside a row; to say why a row can't be chosen, use a message in a row. Notes that follow each other stack `--en-c-note-gap` apart; keep them in a box of their own with no gap, since a parent's gap would add to it. A long note wraps.
- Motion: none.

### Page speckle
- Classes: `.en-speckle`, on an empty area of the page ground.
- State: none.
- Use it on empty areas only: very faint cream flecks, with the occasional one in the accent. Never put it behind list text. Nothing you can select is ever patterned. Text beside it still passes its contrast check.
- Motion: none. Nothing animates.

### Lighter fallback
- Attribute: `data-en-lighter="true"` on `<html>` (or any element, for everything inside it).
- It is for devices that stutter. It drops the soft shadows and the lift and press movement, and keeps everything else: colours, cream focus, the accent underside and the speckle.

### Behaviour script
`components/enamel-components.js` is plain JavaScript with no dependencies and no build step. Load it after the stylesheets. It does only this: opens and closes a picker, keeps focus inside it, moves focus and stops at the ends, selects, cancels and returns focus to where it came from; shows a toast, updates it, and hides it three seconds after its last update, one at a time; and keeps the picker's layer and the toast clear of the hint bar. It sets only the state attributes above and one measurement: on each hint bar's parent element it keeps `--en-c-hintbar-height` at the bar's real height, which grows when its hints wrap, so a picker dialog or toast inside that parent stops just above the bar (the toast the script makes goes in `<body>`). Use one hint bar per parent. Without the script, or while the hint bar is hidden or gone, both stop `--en-size-bar` above the bottom, the bar's height on one line. It never sets colours or timings, and how long a leaving animation lasts comes from the motion tokens. It knows nothing about controllers.

Functions, on `window.EnamelUI`:
- `picker.open(dialog, opener)`: open a `.en-dialog`. Focus goes to the row with `autofocus`, else the current choice, else the first row. `opener` is where focus returns; it defaults to what had focus.
- `picker.up()`, `picker.down()`: move focus one row, stopping at the ends.
- `picker.select()`: choose the focused row. Fires `en-select` on the dialog, with `detail.row` and `detail.value`. On the Cancel row it cancels instead.
- `picker.cancel()`: close without choosing. Fires `en-cancel` on the dialog.
- `picker.close()`: close without an event.
- `picker.isOpen()`: whether a picker is open.
- `toast.show(text, options)`: show a toast, replacing any other. Options: `icon` (an element for the leading icon), `time` (ms it stays after its last update; 3000 by default), `element` (a `.en-toast` already on the page; otherwise the script makes one at the end of `<body>`).
- `toast.update(text)`: change the text and restart the timer (shows a toast if none is showing).
- `toast.hide()`: hide it now.

Keys and taps: while a picker is open the script answers Up, Down, Enter, Escape and Tab itself, before anything else on the page hears them (a capture listener on `window`), and stops them there. A tap on a row selects it. Once the picker closes, keys reach the app again.

An app with its own key or controller handling should check `EnamelUI.picker.isOpen()` at the top of its handler. While it is true, the app must not act on any press. Keyboard presses the script answers never reach the app. Presses the app reads some other way (for example from a gamepad) should go to `picker.up()`, `picker.down()`, `picker.select()` and `picker.cancel()` instead of the app's own actions. That way one press is never acted on twice.

These function names, their options, the `en-select` and `en-cancel` events, and the `data-closing` attribute are part of the system: renaming or removing any of them later is a breaking change.

## Scaling

Two separate controls, never mixed.

**The user's text size.** Enamel never sets the root font size, so 1rem stays the user's own default. Text, and what belongs to text, grows with it.

**The interface size.** `--en-root-size` on `<html>`, for example `--en-root-size: 112.5%`, scales everything, pixels included, the way browser zoom does, through CSS zoom on the page's root. At 100% it does nothing. A future "interface size" setting would use it.

**Which unit, by one question: should this grow when the user makes text bigger?**
- Yes is rem: text, line spacing, vertical space between blocks of text, row heights, widths of things that hold text.
- No is px: borders, hairlines, the focus ring and its offset, corners, shadows, the lift, and side padding that would squeeze text if it grew.

Anything that holds text uses a minimum height, never a fixed one, so wrapped text makes it taller. Widths in rem never exceed their space. Breakpoints are written in rem, so a large text size gets the narrower layout. Every part holds together with the browser's text size at 200%.

**The grid unit.** Every size is a multiple of 4 in its own unit: 0.25rem if it grows with text, 4px if it does not. Both are 4px at the default text size. Round up when unsure. `tools/check_guide.py` enforces this. The exceptions, each for a clear reason:
- hairlines of 1 or 2px (rims, lips and edges), including Steam's `--en-radius`;
- pills (999px);
- speckle dots and their spacing;
- ratios (line height, letter spacing, focus growth) and durations;
- text sizes, which keep Steam's sizes;
- Steam baseline values, which are never rounded: the `--en-shadow-` shadows, `--en-focus-affordance` and the backdrop blur;
- the formula and upper limit of a growing size. A value written as a `clamp()` is checked at its base.

**Nothing reads the screen.** No size comes from the screen's size, a device or an aspect ratio; text and gutters still grow on wide pages, by at most a fifth, from a page 100rem wide to 160rem.

**Apps follow the same scale.** An app's own layout asks the same question of each size and uses Enamel's tokens where they exist.

## Motion

Components move on their own; apps add no motion CSS. Only things you press (buttons and picker rows) move physically. Every duration and curve is a Group D token, and motion only marks focus or a change of state. Focus motion restarts each time focus arrives, whether by `:focus-visible` or `data-focused="true"`.

- **Reduced motion** applies when the device asks for it (`prefers-reduced-motion: reduce`) or when `data-en-motion="reduced"` is set on `<html>` (or on any element, for everything inside it). There is no pulse, no scale, no narrowing ring, no rising or dropping and no sliding or growing; those changes are instant, a tile's ring simply appears, a focused button turns cream at once and a press only darkens. Colour fades stay, at `--en-motion-fast`. Focus is exactly as visible as in full motion.
- **Full motion** is forced with `data-en-motion="full"` on `<html>`, whatever the device asks for. Use it only when the app has its own motion setting and the user chose full motion there.
- Without the attribute, Enamel follows the device.

## Accents

The accent is a slot. Components use only the active accent: `--en-accent`, `--en-accent-ink` and `--en-accent-glow`. Each named accent is a pair of tokens in Group B, `--en-accent-<name>` and `--en-accent-<name>-ink`. Coral is the default accent; Sage is an example alternate.

- **Select one:** set `data-en-accent="<name>"` on `<html>` for the whole page, or on any element for everything inside it. Without the attribute, the default accent applies. The glow and the focus ring are calculated from the active accent wherever the attribute is set.
- **Add one:** add the two values to Group B of `tokens/enamel.css`, add a `[data-en-accent="<name>"]` rule that points `--en-accent` and `--en-accent-ink` at them, then run `python3 tools/check_guide.py`. The accent check must pass: the accent needs 4.5:1 on `--en-surface-page` and `--en-surface-raised` and 3:1 on `--en-surface-control`; its ink needs 4.5:1 on the accent; and it must be at least 25 (CIE76 Delta E) away from `--en-green`, `--en-yellow` and `--en-red`.
- Components never name a specific accent.
