Accents

An accent is two values, the colour and its ink, plus a passing accent check. Components use only the active accent (--en-accent, --en-accent-ink, --en-accent-glow). Set data-en-accent="<name>" on <html> or on any element to switch it. The default accent is Coral.

The accent check: the accent needs 4.5:1 on the page and on rows, 3:1 on the control surface, its ink needs 4.5:1 on the accent, and the accent must be at least 25 (CIE76 Delta E) away from green, yellow and red so it is never mistaken for a status colour.

Rules

  1. Use only --en- tokens. Never hard-code a colour, size or radius.
  2. Apps use the semantic tokens (Group C), not the grey ramp directly.
  3. The accent appears only for: selected side-menu item, toggle on, slider and progress fill, primary button, status text, "new" dot, the focus ring, the focus underside, the progress speckle's fill and the page speckle's occasional fleck.
  4. Focus: accent ring with a soft glow on tiles, accent ring on toggles; cream fill with dark semibold text on a 4px accent underside on buttons, fields and picker rows; a focused row on a page lifts to --en-surface-control, with muted text stepping up to --en-text-soft.
  5. Satin, never gloss.
  6. Patterns live on the page ground and in progress fills only. Nothing you can select is ever patterned.
  7. One border per element: no rims inside rings, no lips inside outlines.
  8. One focus style per kind of element: cream on a coral underside for things you press, a coral ring for tiles, a lift for rows.
  9. Cream is a neutral; the accent stays the only colour.
  10. Only things you press move physically.
  11. Every size is a multiple of 4 in its own unit (0.25rem if it grows with text, 4px if it does not) unless a listed exception applies.
  12. Ask of every size: should it grow when the user makes text bigger? Yes is rem, no is px. Never set the root font size.
  13. Only one element shows focus at a time.
  14. Labels on the accent use --en-accent-ink, never white.
  15. Green, yellow and red are for success, warning and error only.
  16. System font only. Never add a web font.
  17. No layout is tied to a screen size, a device or an aspect ratio. Nothing in tokens, components, examples or docs names one as a layout target.
  18. Layouts adapt to the space they are given: relative units, min(), max() and clamp(), intrinsic sizing, wrapping, and container queries, so a component responds to its own box rather than to the whole screen.
  19. Breakpoints, where needed, come from the content and are named by what they do ("panels stack when they cannot both fit at their minimum width"), never by a device.
  20. Devices are for testing, never targets.
  21. The smallest supported box is 20rem wide by 15rem tall (320px wide and 240px tall at the browser's normal font size). It is set by its content: a list row with its title and a toggle, and the hint bar with at least two hints on one line, fit in it without overlapping, and every focus ring stays fully visible. More hints wrap onto another line. Below that size the page scrolls; nothing overlaps or is cut off.
  22. No Valve assets: no icons, logos, fonts or class names.
  23. Never put accent-coloured text on --en-surface-control. Keep status text on the page or on a row.
  24. When a row is focused, muted text inside it steps up to --en-text-soft.
  25. Build screens from these components before writing any new CSS.
  26. Apps size their own layout with the same scale, in rem or with Enamel's tokens, never with fixed pixels for anything that holds text; lines, corners, shadows and side padding that would squeeze text stay in px.
  27. The keyword transparent is allowed. The style guide's own layout widths in docs/site.css are allowed.
  28. Motion uses only the motion tokens.
  29. Motion marks focus or a change of state, nothing else.
  30. The focus pulse stops after about five seconds.
  31. Every component must work in reduced motion.
